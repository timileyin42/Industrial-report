# Environment Setup Guide

Step-by-step for the external services this platform depends on. Resend
is already done on your side — not repeated here. After each section,
the exact `.env` / `web/.env` line(s) to fill in are called out.

---

## 1. Cloudflare R2 — export file storage

Used for: generated CSV/report export files (`internal/storage/r2.go`).
Optional at the code level (export jobs just fail with a clear error
until this is set), but needed for the export feature to actually work.

### 1.1 Create the bucket

1. Log into the Cloudflare dashboard → **R2 Object Storage** (left sidebar).
2. If this is the account's first bucket, Cloudflare will prompt you to
   enable R2 — do that first (no charge for the free tier's included
   storage/operations).
3. Click **Create bucket**.
   - Name: `cleanenergyanalytics-exports` (or anything — just make it
     match whatever you put in `R2_BUCKET`).
   - Location: Automatic is fine.
4. Leave the bucket **private** — exports are served through
   time-limited presigned URLs generated by the API (`PresignGet` in
   `internal/storage/r2.go`), never a public bucket URL. Do not enable
   "Public access" on this bucket.

### 1.2 Get your Account ID

Same R2 Object Storage page, right-hand side panel — **Account ID** is
shown there directly (also visible on the main Cloudflare dashboard
overview page for any zone). Copy it as-is.

### 1.3 Create an API token (access key + secret)

1. Still on the R2 page → **Manage R2 API Tokens** (top right).
2. **Create API Token**.
3. Permissions: **Object Read & Write**, scoped to the one bucket you
   just created (not "Apply to all buckets") — least-privilege, per
   CLAUDE.md's security section.
4. TTL: no expiry is fine for a server-side credential like this one,
   but note the date if you'd rather rotate it periodically.
5. Create it — Cloudflare shows the **Access Key ID** and **Secret
   Access Key** exactly once. Copy both immediately; there is no way to
   view the secret again after leaving this screen (if you lose it,
   delete the token and create a new one).

### 1.4 Fill in `.env`

```
R2_ACCOUNT_ID=<from step 1.2>
R2_ACCESS_KEY_ID=<from step 1.3>
R2_SECRET_ACCESS_KEY=<from step 1.3>
R2_BUCKET=<the bucket name from step 1.1>
```

No other Cloudflare-side config is needed — `internal/storage/r2.go`
builds the S3-compatible endpoint itself from `R2_ACCOUNT_ID`
(`https://<account_id>.r2.cloudflarestorage.com`).

## 2. Google Maps — site location picker, autocomplete, lat/lng

Used for: `web/src/components/map/LocationPicker.tsx` (search-a-place +
click-to-drop-a-pin when adding/editing a site, auto-fills lat/lng and
the formatted address) and `web/src/components/map/MapEmbed.tsx`
(read-only embedded map on Site Detail). Both read the **same** key,
`VITE_GOOGLE_MAPS_API_KEY` — but they use two different Google Maps
Platform products on that key, so both must be enabled or one of the
two features silently falls back (LocationPicker degrades to plain
numeric lat/lng inputs; MapEmbed shows its own placeholder).

### 2.1 Create a Google Cloud project (if you don't already have one)

1. https://console.cloud.google.com/ → project selector (top left) →
   **New Project**. Name it something like `clean-energy-analytics`.

### 2.2 Enable billing

Google Maps Platform requires a billing account attached to the project
even though there's a generous monthly free tier (currently $200/mo
credit, which comfortably covers a single-tenant admin dashboard's
usage). Console → **Billing** → link or create a billing account.

### 2.3 Enable the two APIs this app actually uses

Console → **APIs & Services → Library**, search for and **Enable** each:

- **Maps JavaScript API** — powers the interactive map + the pin in
  `LocationPicker.tsx`.
- **Places API** (sometimes shown as "Places API (New)") — powers the
  address-search autocomplete in the same component.
- **Maps Embed API** — powers the simple read-only iframe map in
  `MapEmbed.tsx` on Site Detail.

Do not enable APIs beyond these three for this key — least-privilege
per CLAUDE.md, and it keeps the free-tier usage predictable.

### 2.4 Create the API key

1. Console → **APIs & Services → Credentials → Create Credentials →
   API key**.
2. Immediately click **Edit API key** on the one you just created (skip
   this and the key is usable from anywhere by anyone who finds it in
   a browser network tab — this key ships client-side, so restriction
   is not optional):
   - **Application restrictions → HTTP referrers (websites)**. Add:
     - `https://<your production dashboard domain>/*`
     - `http://localhost:5173/*` (local dev — remove once you no longer
       need to test against this key from a laptop)
   - **API restrictions → Restrict key** → select exactly the three
     APIs enabled in step 2.3.
3. Save.

### 2.5 Fill in `web/.env`

```
VITE_GOOGLE_MAPS_API_KEY=<the key from step 2.4>
```

Remember this is baked into the JS bundle at **build time** (Vite),
not read at container runtime — changing it means rebuilding the `web`
image/bundle, not just restarting a container.

### 2.6 Sanity check after deploying

Open the Add Site page — the address search box and map should render
instead of the plain-number lat/lng fallback. If it falls back, check
the browser console: a `RefererNotAllowedMapError` means step 2.4's
referrer restriction doesn't match the domain you're actually loading
from (http vs https, trailing slash, wrong subdomain, etc.).

## 3. Weather — nothing to set up

`web/src/lib/weather.ts` uses the **Open-Meteo** API
(`api.open-meteo.com`), which is free and keyless — no signup, no API
key, no env var. Nothing to do here; it's called directly with whatever
site lat/lng is on file (which itself comes from section 2 above, or
manual entry).

## 4. MQTT broker admin (device credential automation)

Used for: automatically syncing a device's credential into Mosquitto's
`dynamic-security` plugin the instant it's registered/rotated/revoked —
see `internal/mqttadmin/dynsec.go`. No external account/signup needed,
this is entirely self-hosted infrastructure you already run.

### 4.1 Generate the admin password

```bash
openssl rand -base64 24
```

### 4.2 Fill in `.env`

```
MOSQUITTO_DYNSEC_PASSWORD=<the generated password>
MQTT_ADMIN_USERNAME=admin
MQTT_ADMIN_PASSWORD=<the same generated password>
```

`MOSQUITTO_DYNSEC_PASSWORD` sets this on the broker container's very
first start (it self-bootstraps an `admin` account); `MQTT_ADMIN_USERNAME`/
`PASSWORD` is what the API connects to the broker with as that same
account — they must describe one account, which is why both env vars
hold the same password.

If left unset, device registration/rotation/revocation still works, just
without the broker sync — the API tells you so via a
`broker_sync_warning` field on the response instead of failing silently.

## 5. MQTT public broker address (device setup QR code) — frontend only

Used for: the QR code shown once at device registration/rotation
(`web/src/components/devices/DeviceQRCode.tsx`) — lets an installer scan
the broker address, device ID, and secret with a phone camera instead of
typing a 40+ character secret into a datalogger by hand. Purely a
display convenience; nothing breaks if this is left unset, the QR code
just omits the broker line.

**This is not the same value as `MQTT_BROKER_URL`** in the root `.env` —
that one points at the docker-compose service name `mosquitto`, only
reachable from inside the Docker network. This one needs to be whatever
address a physical device out in the field can actually dial — your
server's public IP or a DNS record for it, **not proxied through
Cloudflare** (Cloudflare's standard proxy only forwards HTTP(S) traffic,
not arbitrary MQTT/TCP — this DNS record needs the grey cloud/DNS-only
setting, or just use the raw IP).

### Fill in `web/.env`

```
VITE_MQTT_PUBLIC_BROKER_URL=mqtt://<your-server-ip-or-unproxied-domain>:1883
```

## 6. Resend — already done

You've already set this up on your end. For completeness, the two env
vars it needs in `.env` are:

```
RESEND_API_KEY=<from your Resend dashboard>
EMAIL_FROM_ADDRESS=<a verified-domain address in Resend>
```

If either is left blank, `internal/email/email.go` falls back to a
logging no-op sender (invite/reset links get printed to the API's logs
instead of emailed) — useful for local dev, not something you want live.

## After filling in `.env` / `web/.env`

- `.env` (root, backend) and `web/.env` are both gitignored — never
  commit real values. `.env.example` (root) and `web/.env.example` are
  the checked-in templates; keep them in sync if you add a new var.
- Rebuild rather than just restart when you change a `VITE_*` value —
  it's compiled in, not read at runtime (see 2.5 above).
- `JWT_SECRET`, `DATABASE_URL` (with its password), `MQTT_PASSWORD`,
  `R2_SECRET_ACCESS_KEY`, and `RESEND_API_KEY` are all real credentials
  — treat `.env` itself the same way you'd treat a password manager
  entry, not a config file to paste into chat, a ticket, or a repo.
